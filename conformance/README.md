# The predictable conformance corpus

This directory is a **specification test**, not a snapshot of behaviour. Every file here was written
by hand from `docs/design/01-ir.md` (IR 1.0, format `pir/1`) **before any parser or checker existed**.
Nothing in it was generated by running the tools. When a tool disagrees with the corpus, the default
assumption is that the tool is wrong; changing a `.expected` file to match an implementation is a
review-visible act and requires a spec citation in the commit message.

The corpus is consumed by:

| Consumer | What it asserts |
|---|---|
| T02 parser | every `valid/**` input parses; every `invalid/**` parse case reports the expected diagnostic |
| T05 `predictable fmt` | `fmt(input)` equals the expected canonical form, and `fmt` is idempotent |
| T06 checker | the diagnostic set for each case equals `expected.diag`, code for code and span for span |
| T16 determinism harness | the `runtime = true` cases produce byte-identical results on all three targets |

---

## 1. Layout

```
conformance/
  README.md            this file — the format contract
  index.toml           the case index: one [[case]] per directory, with its expected codes
  check_corpus.py      self-check: the corpus obeys its own contract (no parser involved)
  valid/
    v01-minimal-scalar/
      case.toml        case metadata
      model.pir        input module
      product.pir      input product (optional)
      run.pir          input run config (optional)
      expected.diag    expected diagnostics (absent ⇒ none expected)
      *.pir.expected   expected canonical form (absent ⇒ input is already canonical)
      data/            modelpoints and table CSVs, for runtime cases only
  invalid/
    e01-cycle-same-period/
      ...
```

A case directory is self-contained. Paths inside a `.pir` file (`source`, `imports`, `modules`,
`assumptions`, `modelpoints`) are resolved relative to the case directory, which is what makes the
sandbox rule of IR §2.9.1 testable: `invalid/e17-table-source-escape` deliberately escapes it.

Case directory names are `v<NN>-<slug>` and `e<NN>-<slug>`; the number is an identity, never
reused, and never renumbered when a case is inserted.

## 2. `case.toml`

```toml
name    = "v01-minimal-scalar"
kind    = "valid"                      # valid | invalid
title   = "The smallest well-formed module"
spec    = ["01-ir.md §2.3", "01-ir.md §5"]   # sections this case exists to pin
entry   = ["model.pir"]                # files fed to the tool, in order
product = "product.pir"                # optional; present ⇒ product-level checks run
run     = "run.pir"                    # optional; present ⇒ run-scoped pass 7 runs
runtime = false                        # true ⇒ the case is expected to execute, not just check
fmt     = true                         # false ⇒ skip the fmt assertion (parse-error cases)
```

`kind = "valid"` means *the model checks*; it may still carry `W0xxx` lints. `kind = "invalid"`
means at least one `E` diagnostic is expected. A `valid` case that produces any `E` diagnostic is a
failure, and so is an `invalid` case that produces none.

## 3. `expected.diag` — the diagnostic contract

Line-oriented, one diagnostic per line, `#` comments and blank lines ignored:

```
<severity> <code> <file>[:<line>[:<col>]] <message substring>
```

- **severity** — `error` or `warning`.
- **code** — either an exact code (`E0201`) or a **family wildcard** (`E05xx`), which matches any
  code in that family. Wildcards are used wherever `01-ir.md` fixes the *behaviour* but leaves the
  number to the diagnostics registry (T03); when T03 assigns the number, the wildcard is replaced by
  the exact code in the same commit. Wildcards never appear for a code the spec already fixes.
- **span** — the file the primary span points into, optionally its 1-based line and column. A line
  given must match exactly; an omitted line asserts only the file. Columns are the byte column of the
  first character of the primary span.
- **column convention** — for a quoted TOML value the span starts at the **first character inside
  the quotes**, which is what `01-ir.md` §3.1's rendered example does (`expr = "bel * 1.05"` carets
  `bel` at column 9). For a list value it starts at the `[`, unless one element is at fault, in which
  case it starts at that element's first character. **Secondary spans are not asserted** — a cycle
  error names two components and the corpus pins only the primary one, because which end of a cycle
  is "primary" is a rendering choice the diagnostics registry owns.
- **message substring** — the rest of the line, matched case-sensitively as a substring of the
  rendered `message` field. It is short on purpose: the corpus pins *what is said about what*, not
  the prose, which `04-verify.md` and the diagnostics registry own.

Lines are **sorted** by `(file, line, col, code)` and the checker's output is sorted the same way
before comparison. The comparison is exact set equality: an unexpected extra diagnostic fails the
case, which is what stops a checker from being noisy.

### 3.1 Diagnostic families

`01-ir.md` fixes these codes normatively: `E0101`, `E0105`, `E0106`, `E0107`, `E0108`, `E0201`,
`E0202`, `E0301`, `E0305`, `E0402`, `E0403`, `E0404`, `E0602`, `E0801`, `E0902`, `E0903`, `E1203`,
`E1402`, `W0101`–`W0105`. The families they imply, and which this corpus uses for wildcards:

| Family | Pass (IR §7) | Covers |
|---|---|---|
| `E00xx` | 1 parse | grammar errors, illegal index forms, unknown keys |
| `E01xx` | — | module / product / run file structure |
| `E02xx` | 2, 3 | resolution, shadowing, time references, cycles |
| `E03xx` | 4 | shapes and broadcasting (plus `E0305`, the enum key policy rule) |
| `E04xx` | 7 | `[[aggregation]]` validation |
| `E05xx` | 5 | dtypes, units, timing tags, lookup key arity |
| `E06xx` | 5 | presence bits — `is_null` / `coalesce` |
| `E08xx` | — | table sources, resolvers, digests |
| `E09xx` | run | runtime traps and solver failures |
| `E12xx` | build | DSL build-time errors (`E1203`) |
| `E14xx` | 5 | basis conversion |

The five checker classes this corpus originally wildcarded were numbered by the diagnostics
registry when the checker (`T06`) landed, and the wildcards were replaced by the exact codes in the
same commit, as this section requires. No wildcard remains:

| Class | Was | Now | Cases |
|---|---|---|---|
| illegal index form (`x[t+1]`, `x[T]`) | `E00xx` | `E0030` | `e08` |
| unresolved name / shadowing / horizon | `E02xx` | `E0203`, `E0204`, `E0205` | `e12`, `e21`, `e14` |
| unit mismatch (add, rate basis, multiply) | `E05xx` | `E0501`, `E0502`, `E0503` | `e05`, `e06` |
| lookup key arity / dtype | `E05xx` | `E0504`, `E0505` | `e09` |
| timing-tag legality, zeroless `Lag` | `E05xx` | `E0506`–`E0509` | `e07`, `e15` |

### 3.2 Runtime cases

A case with `runtime = true` carries `data/` and an `expected.trap.json` or `expected.results.csv`.
`expected.trap.json` is the `E0902` envelope of IR §9.3.1 with `doc_url` and `operands` optional;
fields present in the file must match exactly.

## 4. `*.pir.expected` — the canonical form contract

If `model.pir.expected` exists, `fmt(model.pir)` must equal it byte for byte. If it does not exist,
`fmt(model.pir)` must equal `model.pir` byte for byte — every input in this corpus is authored in
canonical form except where a case exists precisely to exercise `fmt` (`v05-canonical-fmt`).

`fmt` must also be idempotent: `fmt(fmt(x)) == fmt(x)` for every file, expected or not (IR §4.1
rule 6). The canonical rules the corpus pins:

1. Intra-`[[component]]` key order is exactly
   `name, kind, dtype, shape, unit, timing, init, expr, doc, tags, output`; absent keys are skipped,
   never emitted as empty.
2. Components keep declaration order. `fmt` never reorders them, and never reorders top-level
   blocks either — §4.1 fixes intra-component order only, and declaration order is the §3.2 tiebreak.
3. Expressions: single spaces around binary operators, no redundant parentheses **except** those
   disambiguating mixed `*`/`+`, which are preserved as written.
4. Floats round-trip shortest (Ryū): `1.05` stays `1.05`, `0.10000000000000001` becomes `0.1`.
5. UTF-8, LF, one trailing newline, no trailing whitespace.

Layout rules `01-ir.md` §4.1 leaves open, fixed by `T05` and pinned by every file here
(`docs/v2/canonical-form.md` §2.3):

6. One `key = value` per line; `;`-joined pairs are split onto their own lines.
7. Exactly one blank line before every `[section]` header and **nowhere else** — §9.3 rule 6 requires
   formatting to be invisible to a digest, which it cannot be if `fmt` preserves blank lines. The
   `base.pir` files of `v01`, `v02` and `v08` were authored with a blank line between their header
   keys and their assumption values and have been reformatted accordingly.
8. Comments are preserved at column 0 immediately above the item they precede; inside a
   `[[component]]`, whose keys rule 1 reorders, they are hoisted to just under the header. An array
   is inline unless it has more than one element and any element is an array or an inline table.

## 6. Adding a case

1. Pick the next free number in `valid/` or `invalid/`.
2. Write the `.pir` **in canonical form** (§4) unless the case is about `fmt` or about a parse error.
3. Cite the spec section in `case.toml.spec`. A case with no citation is not a conformance case; it
   belongs in the implementation's own unit tests.
4. Register it in `index.toml` with its expected codes.
5. Run `python3 conformance/check_corpus.py`. It verifies registration, span line/column validity,
   code legality, sorting, valid/invalid consistency and the canonical text rules — everything about
   a case that can be checked without a parser.
6. Keep it minimal. One error class per invalid case; the corpus is read by humans diagnosing a
   failing checker, and a 200-line reproduction is not a reproduction.
