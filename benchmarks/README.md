# predictable-benchmarks

The cross-engine benchmark of [`03-engine.md` §11](../docs/design/03-engine.md). Five
scenarios, four implementations, one correctness gate that runs **before** any timing is
recorded.

The published write-up — methodology, results, caveats — is
[`docs/v2/benchmarks.md`](../docs/v2/benchmarks.md). This file is the operating manual.

## Layout

```text
benchmarks/
  bench/
    basis.py            assumption sets, tables, modelpoint generation (shared by all engines)
    scenarios.py        the five scenarios, and the sizes each engine is asked for
    workdir.py          materialise a predictable run directory at size M
    outputs.py          the comparison contract every engine returns
    gate.py             the correctness gate and its metric
    timing.py           wall time, peak RSS
    harness.py          gate first, then timings
    report.py           the published Markdown
    docs_update.py      refreshes the generated tables in docs/v2/benchmarks.md
    engines/
      predictable_cli.py    predictable, through the CLI
      numpy_ref.py          the hand-written NumPy reference
      cashflower_impl.py    cashflower driver
      cf_models/            the cashflower models, one module per scenario
      modelx_impl.py        modelx/lifelib driver
      mx_models.py          the modelx formulas
      scalar_basis.py       scalar table lookups, shared by the two scalar engines
  results/              results.json + results.md, regenerated by `python -m bench`
  tests/                the benchmark's own regression suite
```

## Setup

```console
$ cd benchmarks
$ uv venv .venv --python 3.12
$ uv pip install --python .venv/bin/python cashflower lifelib modelx numpy pandas pyarrow pytest
$ cargo build --release -p predictable-cli    # from the repository root
```

## Running

```console
# the gate on its own — fast, and the only thing CI must not skip
$ .venv/bin/python -m bench --gate-only

# the full published run
$ .venv/bin/python -m bench --repeats 5 --threads 1,2,4,8

# one scenario, one engine
$ .venv/bin/python -m bench --scenario term_annual --engine predictable --engine numpy
```

`python -m bench` writes `results/results.json` and `results/results.md`, and exits
non-zero if the gate failed. **A failed gate suppresses the timings for that scenario**;
they are not written and the reason is recorded in the report.

## Tests

```console
$ .venv/bin/python -m pytest tests -q
```

`tests/test_gate.py` proves the gate can fail — including the two cases that make the
metric defensible: a component whose scale dwarfs its own noise floor, and a component
solved to zero. `tests/test_reference_agreement.py` runs all four engines on all five
scenarios and pins the NumPy reference to the committed goldens in `models/*/expected/`.

## Adding a scenario

1. Add the model to `models/` (it is the same corpus the rest of the project uses).
2. Add a `Scenario` to `bench/scenarios.py` with its periods and its per-engine size caps.
3. Implement it in `numpy_ref.py` first, and make it reproduce the committed goldens.
4. Then, and only then, implement it in the other engines.

Step 3 before step 4 is not a style preference: the NumPy reference is the yardstick the
gate uses, so it has to be pinned to something external before anything is compared to it.
